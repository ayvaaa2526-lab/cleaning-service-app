# Clearly Cleaning v4.1

Калькулятор и заявки на уборку: русский, английский, грузинский; GEL и USD.
Cloudflare Workers + D1 + Better Auth 1.7.6. Доступ из обычного браузера, без ChatGPT.

## Что изменилось

- Регистрация по email и паролю, вход и выход с серверной сессией.
- Заявки, комментарии и статусы сохраняются в D1 и доступны с другого устройства после входа.
- Каждый пользователь видит только свои заявки. Администратор назначается по ID пользователя в настройках Worker.
- Статусы: новая, подтверждена, выполнена, отменена.
- Сервер сам рассчитывает цену и проверяет услуги, площадь, поля и будущую дату по Тбилиси.
- Повтор запроса после сбоя сети не создаёт второй заказ.
- Выбранные услуги сохраняются при переключении языка, валюты и типа уборки.
- Старые clearlyOrders не удаляются и отображаются как демозаявки этого устройства. Они не переносятся автоматически в аккаунт.

## Перед публикацией

Ветка release/v4.1 подготовлена отдельно от main. Изменение main запускает существующий деплой Cloudflare, поэтому сначала настройте сервер.

1. В Cloudflare откройте D1 и проверьте имя и ID созданной базы. В wrangler.jsonc указан предложенный ранее clearly-cleaning-db и ID из переписки 3c155048-82df-4bd2-a072-a09dc8986d91; соответствие этой базы аккаунту ещё не проверено.
2. В нужной базе выполните migrations/0001_auth.sql, затем migrations/0002_bookings.sql через консоль D1. Альтернатива на компьютере: npm run db:remote после входа в Wrangler. Выберите один способ и не запускайте те же CREATE TABLE повторно вручную. Таблицы имеют префикс clearly_; существующие таблицы не удаляются.
3. В настройках Worker damp-pine-281a добавьте секрет BETTER_AUTH_SECRET: случайное значение минимум 32 символа, лучше 32 случайных байта. Генерируйте его локально (например, openssl rand -hex 32) и вставляйте только в Cloudflare как Secret. Не добавляйте значение в GitHub или чат.
4. В настройках сборки Cloudflare установите команду сборки npm run build, команду публикации npx wrangler deploy, корневую папку репозитория. Worker и привязка DB описаны в wrangler.jsonc. Секрет должен быть доступен Worker во время работы, а не только во время сборки.
5. После настройки объедините PR с main. Убедитесь, что деплой успешен, зарегистрируйте свой аккаунт, создайте тестовую заявку и войдите с другого устройства.
6. Для админ-панели возьмите ID своего зарегистрированного пользователя из таблицы clearly_user. Добавьте его в ADMIN_USER_IDS в wrangler.jsonc и опубликуйте изменение. Не назначайте администратора по неподтверждённому email. Поле пустое по умолчанию — администраторов нет.

Если в базе уже есть таблицы clearly_*, сначала проверьте их структуру; не удаляйте пользовательские данные для применения миграции. Если миграции выполнены вручную, не запускайте db:remote без согласования истории миграций Wrangler.

## Локальная разработка

Нужен Node.js 24 и npm. npm ci устанавливает версии из lockfile.

Создайте игнорируемый .dev.vars с локальными значениями:

```text
BETTER_AUTH_URL="http://localhost:8787"
BETTER_AUTH_SECRET="<случайный локальный секрет минимум 32 символа>"
```

```sh
npm ci
npm run db:local
npm run dev
```

Папка dist содержит только публичные HTML/CSS/JS и manifest, без серверного кода, базы и секретов.

## Проверки

```sh
npm run check
npm run test:integration
```

- Unit/DOM: расчёт цены, подмена параметров, календарные даты, сохранение выбранных услуг, экранирование старых данных, отключённый сервер.
- Integration: Better Auth с локальной D1; регистрация, вход, отзыв сессии при выходе, изоляция двух аккаунтов, CSRF, защита админ-операций, сохранение комментария, отсутствие дублей.
- wrangler deploy --dry-run: сборка Worker без публикации.

Интеграционные тесты используют только локальную D1 и удаляют созданные тестовые аккаунты и локальные счётчики ограничений. Не используйте этот сценарий для production.

2 октября 2026 повторно прошли 7 unit/DOM-тестов, интеграционные проверки локальной D1 и dry-run сборка Worker. Локальный dev-сервер запущен. В Chromium прошли регистрация, вход/выход, создание заявки, сохранение после перезагрузки, запрет доступа без входа и мобильная проверка RU/EN/KA. Production smoke test пока не выполнен: Cloudflare не авторизован, запись через GitHub-интеграцию вернула 403.

## Текущие ограничения

- Отправка писем, подтверждение email и восстановление пароля ещё не подключены. Об этом сказано в форме регистрации. Доступ администратора задаётся только по проверенному ID.
- USD использует фиксированный расчётный курс 1 USD = 2,7 GEL, не биржевой курс.
- Сохранение заявки не означает подтверждение уборки или оплату. Платежи и уведомления исполнителю не подключены.
- История показывает последние 200 заявок. Пагинация и импорт демозаявок пока не реализованы.
- Перед публичным запуском нужно проверить расход CPU при входе на фактическом тарифе Cloudflare и провести проверку на опубликованном сайте. Платный тариф этой правкой не включается.
